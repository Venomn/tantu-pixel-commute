# 痰途 · 全勤之路

[开始游戏](https://venomn.github.io/tantu-pixel-commute/) · Godot 浏览器游戏

Godot 4.4.1 / GDScript 制作的浏览器掌机像素风恶搞通勤游戏。无服务端业务，无付费素材，无额外依赖。

## 玩什么

骑自行车完成连续五天通勤。路人按类别、日期、路线概率清嗓吐痰，1.3 秒预警后发射真实弹道；没有防护时命中一次，当天结束。迟到也失败。可以刹车等弹道飞过、冲刺穿行、按铃让路，选择公园绕行或施工近道。擦弹获得结算奖金，路上捡金币。每趟出门算一局：选临时强化、骑行躲避、结束回改装铺、买永久装备，再出门。成功推进到下一天，失败重试当天；完成五天后可以带着财产开始新一周。

- 首页只有「开始」，新游戏直接进入连续五天通勤，不再选择模式。单日基准 390–450 秒。肉鸽版完整五日模拟约 41 分钟；含重试、结算和改装目标约 40–65 分钟，真人通关时间会因熟练度变化。
- 原创 GBA 时代掌机 RPG 风格：16×16 地面瓦片、小比例骑行精灵、两帧踏板、左右转向姿态、分层树冠、瓦顶房屋、花丛、围栏和复古对话框。未使用宝可梦游戏原版素材。
- 自行车、摩托车、小汽车在不同车道行驶；有前方慢车和后方超车，会随机急停、加速、清嗓吐痰。红灯提示急停，黄色速度线提示加速。
- 剐蹭只减速并扣体力，不直接结束游戏；没有防护时吐痰命中仍一口出局。同屏最多四辆车，保留一条没有车辆占用的车道。
- 路边与车内吐痰共用危险数量限制（最多两个正在预警/飞行的吐痰或垃圾危险）和 0.75 秒清嗓间隔；贴脸时取消车辆吐痰，避免无反应时间的出局。
- 原创程序合成五首音乐、十五种音效；清嗓时背景音乐降低。
- 浏览器本地存档：成功当天立即保存下一天进度，刷新不重置已完成日期；失败重来当天，已捡金币与购买装备保留。v1/v2 存档自动迁移为 v3，保留原金币、配件和日期；写入采用临时文件替换。不会跨浏览器或设备同步。
- 失去焦点自动暂停，暂停同时停止声音；切回后需手动继续。

旧存档仍可继续，保留原日期、金币、装备及原有路程长度；界面不再标注模式。

## 金币与装备

首次游玩有 80 金启动资金；之后新一周继承钱包和装备，不重复发启动资金。路上每枚金币值 3 金，成功打卡基础奖金 100 金，擦弹奖金到达后结算；垃圾回投命中原车另奖 12 金。失败保留拾取和回投收入，直接进入商店购买装备再战。钱包上限 9999 金。

购买后永久拥有，跨局、跨周保留，换装和卸下免费。骑行、防御、攻击、辅助四个槽位每类一件，可同时组合四件装备。主菜单「开始」会确认重置日期进度，金币和装备仍保留。

| 装备 | 金币 | 效果 |
|---|---:|---|
| 轻便齿盘 | 80 | 体力恢复 17 → 23 / 秒 |
| 灵敏刹车 | 80 | 加减速响应 140 → 220 |
| 观察后视镜 | 80 | 延长清嗓预警约 0.3 秒 |
| 防痰护盾 | 100 | 自动挡一次吐痰，18 秒重新充能 |
| 打工人雨伞 | 140 | E 主动撑开，挡痰 2.5 秒，冷却 8 秒 |
| 文明泡泡炮 | 180 | F 向前发射，冷却 3 秒；消除路径上的痰，命中车辆让其 6 秒不能吐痰或扔垃圾 |
| 招财磁铁 | 100 | 吸取附近金币，与机械臂占用同一辅助槽 |
| 垃圾回投机械臂 | 320 | 自动抓取近身垃圾，追踪扔回原车；冷却 7 秒，命中后原车 8 秒不能吐痰或扔垃圾 |

55% 的小汽车带有红色「垃」标志，在合适位置以概率选择扔垃圾，先给 1.2 秒红色落点预警，再有 0.8 秒飞行动画。垃圾落地后持续占据路面，没有兔子跳次数时撞到立即失败。护盾和雨伞只挡痰；机械臂冷却时仍需避开垃圾。垃圾、吐痰共用危险数量限制，机械臂回投始终指向原来那辆车。

## 局内强化

每局出门，以及路程约 25% / 50% / 75% 时，从随机三张卡中选择一张。选择期间计时和危险暂停；使用数字 1 / 2 / 3 或点击。九种强化可以叠加到各自上限，已满级的不再出现。

| 强化 | 本局效果 |
|---|---|
| 灵活脚踝 | 转向速度 +25%，最多两层 |
| 能量汽水 | 立即补满体力，恢复 +8/秒，最多两层 |
| 防污贴纸 | 自动挡一次痰，最多选三次，不挡垃圾 |
| 摸鱼奖金 | 每枚金币额外 +2 金，最多两层，收入永久保留 |
| 顺风快递 | 巡航速度 +12，冲刺 +20，最多两层 |
| 幸运口袋 | 吸币范围 +65，可叠加永久磁铁，最多两层 |
| 便携泡泡机 | 本局可按 F 发射；已有永久泡泡炮则变成三向散射 |
| 超频电池 | 装备冷却乘以 0.8，最多两层；有相关装备或临时武器时才出现 |
| 兔子跳 | 自动躲过一次地面垃圾，最多选两次 |

所有临时强化在结算后清空。成功、被命中、迟到或主动结束，都直接进入改装铺并显示本局收入。途中刷新会结束这一局，回到商店；已保存的金币和装备保留，临时强化不恢复。存档仅属于当前浏览器/域名。

金币采用圆形金色轮廓、货币符号、闪光与阴影；拾取有粒子、深色底的加钱飘字和钱包闪动。改装铺与强化卡分别展示永久装备和本局效果。

## 操作

| 操作 | 键盘 |
|---|---|
| 左右转向 | A / D 或左右箭头 |
| 冲刺 | W / 上箭头 / Shift |
| 刹车 | S / 下箭头 |
| 车铃 | 空格 |
| 雨伞（装备后） | E |
| 泡泡炮（装备后） | F |

也可按住画面底部按钮操作。手机建议横屏。Web 版需要支持 WebGL 2 和 DecompressionStream 的较新浏览器；声音由首次交互启用。

## 打开工程

用 Godot 4.4.1 打开 `project.godot`，运行主场景。采用 Compatibility 渲染器、单线程 Web 导出，不依赖 SharedArrayBuffer 或特殊跨域隔离响应头。

```sh
python3 tools/subset_font.py # 需要安装 fonttools；从完整字体生成游戏字形
godot --headless --path . --editor --import --quit
godot --headless --path . --script tests/run_tests.gd
godot --headless --path . --script tests/traffic_tests.gd
godot --headless --path . --script tests/equipment_tests.gd
godot --headless --path . --script tests/roguelite_tests.gd
godot --headless --path . --script tests/ride_simulation.gd
godot --headless --path . --export-release Web dist/index.html
python3 tools/prepare_web.py
node --test tests/web_loader_tests.cjs
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

浏览器访问 `http://127.0.0.1:8765`。不要直接双击导出的 HTML；WebAssembly 需要 HTTP 服务。原生版不需要最后三步。

`prepare_web.py` 压缩引擎和资源包，显示实际下载量、速度和预计剩余下载时间；下载后单独显示引擎启动阶段。SHA-256 校验后缓存压缩文件，资源变化按内容版本重新下载；缓存受限、损坏或额度不足时仍可正常下载。连续 25 秒无数据会提示重试。每次改游戏文案，先运行 `subset_font.py`（需要 FontTools）再导出；完整字体位于排除导出的 `tools/fonts/`，构建检查会阻止遗漏新字形。

## 文件

- `scripts/game.gd`：状态机、实体、真实弹道、输入、存档、像素绘制及界面。
- `scripts/perks.gd`：九种本局强化的效果说明、叠加上限与图标。
- `scripts/equipment.gd`：八件装备的价格、槽位与商店文案。
- `scripts/traffic.gd`：三种车辆的速度状态、相对运动、吐痰出发点和连续碰撞。
- `tools/make_pixel_art.py`：用原始像素网格可复现生成 37 个原创素材，无 Python 第三方库依赖。
- `scripts/rules.gd`：概率、时间、连续碰撞和存档校验。
- `tools/make_audio.py`：可复现的原创音乐和音效生成脚本。
- `tests/run_tests.gd`：51 项规则与场景集成检查。
- `tests/traffic_tests.gd`：70 项车流、预警、密度和生命周期检查。
- `tests/equipment_tests.gd`：51 项金币、换装、主动防御/攻击、垃圾回投、存档迁移及生命周期检查。测试使用隔离 QA 存档。
- `tests/roguelite_tests.gd`：44 项三选一、真实效果、结算、永久资产、刷新与存档迁移检查。
- `tests/render_roguelite.gd`：商店、强化卡和金币的固定 GPU 视觉检查场景。
- `tests/render_equipment.gd`：商店和完整装备的真实 Godot GPU 渲染检查（固定场景，不代表随机通关）。
- `tests/render_traffic.gd`：真实 Godot GPU 渲染的固定视觉检查场景（不随 Web 游戏导出）。
- `tests/ride_simulation.gd`：只通过正常方向输入完成全程的模拟骑手；不修改角色坐标、路程、危险或碰撞。
- `QA.md`：验证范围和局限。

## GitHub Pages 发布

当前站点使用 `main` 分支的 `/docs` 目录发布。Godot 源码在仓库根目录，已导出的游戏资源在 `docs/`；`.nojekyll` 让 Pages 直接发布静态文件。

更新游戏时先按上面的命令运行检查、导出到 `dist/` 并执行 `tools/prepare_web.py`，再把 `dist/` 中的构建文件复制到 `docs/`，保留 `docs/.nojekyll` 和 `docs/.gdignore`，提交并推送即可触发 Pages。引擎和游戏资源使用相对路径，支持仓库子路径。

浏览器存档按站点保存；GitHub Pages 与原 Sites 域名不共享存档。
